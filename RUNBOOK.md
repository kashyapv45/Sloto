# SaaS Engine Operations Runbook

This document provides operational context, diagnostic commands, and resolution paths for alerts generated by the SaaS Engine Prometheus alerting rules.

---

## Alert: HighErrorRate

**Severity**: `CRITICAL`
**Route**: `pagerduty`

### What it means
The global API error rate (HTTP 4xx and 5xx responses) has exceeded 5% of total traffic for a sustained 5-minute period. This usually indicates a widespread failure in a core dependency or a severe application bug.

### Diagnostic Steps
1. **Check the Grafana Dashboard**:
   - Open the "SaaS Engine - Tenant Observability" dashboard.
   - Check if the errors are isolated to a specific `tenantId` or global.
2. **Check Logs (Serilog / OpenTelemetry)**:
   - Query logs for exceptions: `level="Error" OR level="Critical"`.
   - Look for `NpgsqlException` (database issues) or `RedisConnectionException` (cache issues).
3. **Verify Health Check Endpoint**:
   - Run: `curl -v http://localhost:8080/health/ready`
   - Look for failing subsystems in the JSON response (e.g., `postgresql: Unhealthy`).

### Escalation Path
- Primary on-call engineer.
- Escalation to Database/Platform Team if `NpgsqlException` dominates logs.

### Resolution Steps
- **Database Overload**: If PostgreSQL is overloaded, consider scaling up the database instance or scaling out read replicas if Pro/Standard tenants are affected.
- **Cache Failure**: If Redis is unreachable, the system attempts to degrade gracefully, but check network peering and restart the Redis pods if necessary.
- **Bad Deployment**: If this occurred immediately after a deployment, initiate an automatic rollback of the `SaasEngine.Api` deployment.

## Alert: JobQueueBackedUp

**Severity**: `WARNING`
**Route**: `slack`

### What it means
The Hangfire background job queue depth has exceeded 1000 pending jobs for more than 10 minutes. Job processing workers are falling behind the rate of job creation.

### Diagnostic Steps
1. **Check Hangfire Dashboard**:
   - Navigate to `http://<admin-url>/jobs/dashboard` (requires Admin VPN and JWT).
   - See which queues are backed up (e.g., `default`, `enterprise-xyz`, `critical`).
2. **Check Job Execution Latency**:
   - Look at the "Processing" tab to see if jobs are taking significantly longer than usual.
   - Long-running jobs are often caused by slow external API dependencies or heavy database contention.
3. **Check Worker Metrics**:
   - See if CPU/Memory utilization of the `SaasEngine.Api` containers is maxed out.

### Escalation Path
- Primary on-call engineer during working hours.

### Resolution Steps
- **Scale Out**: Increase the replica count of the `SaasEngine.Api` deployment. More instances mean more Hangfire worker threads processing the queue.
- **Poison Pills**: If a specific job type is failing repeatedly and backing up the queue with retries, consider pausing/deleting those jobs in the Hangfire dashboard.

## Alert: SlowDatabaseQueries

**Severity**: `WARNING`
**Route**: `slack`

### What it means
The 99th percentile (p99) response time for database queries has exceeded 500 milliseconds for 5 minutes. This degrades the user experience and can lead to connection pool exhaustion.

### Diagnostic Steps
1. **Identify Slow Queries via Distributed Tracing**:
   - Open Grafana Tempo / Jaeger.
   - Filter for spans with `db.system = "postgresql"` and `duration_ms > 500`.
   - The trace will include the exact SQL statement (`db.statement`).
2. **Identify Impacted Tenants**:
   - Check if the slow query span contains a specific `tenantId` attribute. Enterprise tenants have dedicated connections, while Standard/Pro share a database.
3. **Analyze Query Plan**:
   - Connect to the database and run `EXPLAIN ANALYZE` on the identified query.

### Escalation Path
- Database Administrator or Platform Team during working hours.

### Resolution Steps
- **Missing Index**: Add missing indexes identified in the query plan via an EF Core migration in the `SaasEngine.Admin` project.
- **Connection Pool Exhaustion**: If the database server CPU is low but queries are queued, increase the connection pool size limit (append `Max Pool Size=200;` to connection string).
- **Tenant Migration**: If a Standard/Pro tenant has grown too large, initiate a migration to the Enterprise tier (dedicated database).

## Alert: AuditLogFailure

**Severity**: `CRITICAL`
**Route**: `pagerduty` (Immediate)

### What it means
A write to the `audit_events` table failed. The application is designed to prevent data mutations if the corresponding audit trail cannot be immutably saved. **This is a critical compliance and security incident.**

### Diagnostic Steps
1. **Check Audit Write Role**:
   - Ensure the application connection string used for auditing is still valid and has the `saas_audit_writer` role.
   - Verify the `saas_audit_writer` role has exactly `INSERT` privileges on `audit_events` and nothing else.
2. **Check Disk Space**:
   - The primary database volume may be full, preventing new row insertions.
3. **Check Connection**:
   - Check if the dedicated "AuditConnection" string is correctly pointing to the database.

### Escalation Path
- Security & Compliance Team.
- Primary on-call engineer.

### Resolution Steps
- **Disk Full**: Expand the database storage volume immediately.
- **Role Permissions**: Re-apply the role grants via the Admin service if permissions were accidentally revoked.
- **Failing Over**: If the primary database is experiencing a split-brain or read-only mode during a failover, wait for the primary election to stabilize. No tenant writes should succeed until audit logging is restored.
