3.2 Tenant Isolation Model â€” Hybrid Strategy
Three tenant isolation tiers are supported, selected at tenant onboarding time and stored in the TenantRegistry:
Standard tier: Shared database, shared schema. EF Core Global Query Filters enforce TenantId on every query. Zero connection overhead.
Professional tier: Shared database, tenant-schema-per-tenant (PostgreSQL schema isolation). Slightly stronger isolation, same infra.
Enterprise tier: Dedicated database. ITenantConnectionResolver dynamically resolves the connection string from an encrypted vault (Azure Key Vault / AWS Secrets Manager) at request time. Connection pooling is managed per-tenant via a ConcurrentDictionary<Guid, IDbContextFactory>.

3.3 Native AOT â€” Resolved Strategy
The original spec's goal of a sub-20 MB, single-digit cold-start binary is achievable but requires a deliberate dual-path data access strategy. EF Core's runtime expression compilation is incompatible with NativeAOT. The solution:
AOT-safe hot path: All runtime query paths (API handlers, background jobs) use Dapper with pre-compiled SQL. Dapper has no reflection-based runtime code generation and is fully AOT-compatible.
Non-AOT admin service: A separate internal Admin API (not exposed publicly) retains EF Core for migrations, seeding, and backoffice operations. It is deployed as a standard trimmed (non-AOT) binary.
Trimming config: PublishAot=true is set on the API project. All JSON serialization uses source-generated JsonSerializerContext â€” never reflection-based JsonSerializer.
Validation: Benchmark on target container: docker run --rm saas-engine:aot â€” binary size must be <20 MB, /health must respond in <10 ms on cold container start.

4. Core Services & Interfaces
4.1 ITenantService â€” The Foundation
Scoped per HTTP request. Resolved from the request JWT (sub claim contains tenantId). Provides: CurrentTenantId, CurrentTier, GetConnectionString(), GetPlan(). Must throw TenantNotResolvedException if called outside an HTTP context (guards against accidental access in singleton services).
4.2 IPlanPolicyService â€” Feature Enforcement
Enforces per-tenant plan limits. Backed by Redis (hot cache, 60 s TTL) with database fallback. Policies are evaluated at the use-case handler level via a MediatR pipeline behavior â€” not in controllers.
EnforceSeatsAsync(tenantId) â€” throws PlanLimitExceededException if seat count >= plan.MaxSeats
EnforceApiRateAsync(tenantId, endpoint) â€” sliding window rate limiter via Redis INCR + EXPIRE
IsFeatureEnabledAsync(tenantId, featureKey) â€” reads feature_flags table, Redis-cached
4.3 IAuditService â€” Immutable Audit Trail
All write operations (CREATE, UPDATE, DELETE on tenant-owned resources) emit an AuditEvent via a MediatR notification handler. The audit store is INSERT-only â€” no UPDATE or DELETE operations are permitted on audit_events, enforced at the database role level (audit_writer role has INSERT only).
Audit payload stores: actor identity, action, resource type + ID, diff hash (SHA-256 of before/after JSON), timestamp (UTC, nanosecond precision).
GDPR erasure: user personal data is anonymized in the source table. Audit records retain the action record but replace PII fields with [REDACTED] + erasure_event_id foreign key.
4.4 IEventBus â€” Inter-Slice Communication
In-process event bus using MediatR INotificationHandler for synchronous in-process delivery. For cross-service or async delivery, events are written to the outbox_events table within the same database transaction as the triggering operation (transactional outbox pattern). A background Hangfire job polls the outbox and publishes to the configured broker (RabbitMQ or Azure Service Bus).

5. Observability Stack
The original spec had no observability. A production SaaS engine is undeployable without structured logging, distributed tracing, and metrics. This section defines the complete stack.
5.1 Distributed Tracing â€” OpenTelemetry
SDK: OpenTelemetry .NET SDK with OTLP exporter.
Auto-instrumented: ASP.NET Core, HttpClient, EF Core (slow query spans), Hangfire jobs, Redis operations.
Every trace carries: tenantId, planTier, userId as span attributes â€” enabling per-tenant trace filtering in Grafana Tempo or Jaeger.
Sampling: Head-based 100% sampling for errors; 10% for successful requests. Configurable per-tenant for enterprise tier.
5.2 Structured Logging â€” Serilog
Sinks: Console (JSON, for container log aggregation), OpenTelemetry (log bridge to OTLP).
Enrichers: TenantId, CorrelationId, RequestPath, MachineName, Environment.
Log levels: Information default; Warning for slow queries (>200 ms); Error for unhandled exceptions; Critical for security events (auth failure, tenant bypass attempt).
PII scrubbing: Serilog destructuring policy strips email, phone, IP address fields before emission.
5.3 Metrics â€” OpenTelemetry Metrics
Custom meters: saas.tenant.requests (counter, by tenantId + endpoint), saas.query.duration (histogram, by tenantId + table), saas.plan.limit.exceeded (counter, by tenantId + limitType), saas.job.duration (histogram, by jobType).
Export: OTLP to Prometheus scrape endpoint (/metrics). Grafana dashboards for per-tenant request rates, error rates, job throughput.
5.4 Health Checks
GET /health/live â€” liveness: always 200 (process alive).
GET /health/ready â€” readiness: checks DB connectivity, Redis ping, Hangfire server status. Returns 503 if any fail.
GET /health/startup â€” startup: verifies schema migrations applied, tenant registry loaded.

6. Background Job Architecture â€” Hardened
6.1 Hangfire with Redis Backplane
Hangfire is configured with Redis as the storage backplane. All jobs carry a TenantId in their context, resolved by a custom IJobActivator that creates a tenant-scoped DI scope for each job execution.
6.2 Idempotency & Distributed Locking
Every job carries an idempotency_key (deterministic hash of tenantId + jobType + businessKey). Hangfire's built-in DisableConcurrentExecution attribute prevents parallel execution of the same job type.
Distributed locks for multi-instance deployments use Redis SETNX with a 30-second TTL. Jobs that fail to acquire a lock are requeued with exponential backoff (5 s, 30 s, 5 min, 1 hr).
Outbox poller: runs every 5 seconds, processes up to 100 pending events per cycle, marks events as Processed or Failed (max 5 attempts, then moves to dead-letter table).
6.3 Tenant-Scoped Job Scheduling
Enterprise tenants can define custom cron schedules for their jobs via the API (POST /tenants/{id}/jobs).
Standard/Pro tenants run on shared cron schedules defined at the platform level.
Job isolation: Enterprise tier jobs run in a dedicated Hangfire queue (enterprise-{tenantId}) with priority routing. Standard jobs share the default queue.

7. Security Architecture
7.1 Authentication & Authorization
Authentication: JWT Bearer tokens issued by the platform's own identity service (or delegated to Auth0 / Azure AD B2C for enterprise SSO). Token contains: sub (userId), tid (tenantId), plan, roles claims.
Authorization: Policy-based via ASP.NET Core IAuthorizationHandler. Policies: TenantMember (tid matches), TenantAdmin (role=admin + tid matches), PlatformAdmin (internal role, no tid required).
MFA: TOTP-based (RFC 6238) for admin accounts. FIDO2/WebAuthn support for enterprise tier.
7.2 Connection String Security
Enterprise tenant connection strings are never stored in plaintext. They are encrypted with AES-256-GCM using a key stored in Azure Key Vault / AWS KMS.
ITenantConnectionResolver decrypts on first request, caches the decrypted string in a scoped memory store (not Redis â€” to prevent cross-node exposure). Cache TTL: 15 minutes.
Connection strings are rotated on a schedule via the Tenant Lifecycle API without downtime.
7.3 GDPR Compliance Pipeline
Right to Erasure (Article 17): DELETE /tenants/{id}/users/{userId}/erase triggers the erasure pipeline: (1) anonymize PII fields in users table, (2) replace PII in audit_events with [REDACTED], (3) emit UserErasedEvent for downstream services (email, analytics, CRM).
Data Portability (Article 20): GET /tenants/{id}/export generates a ZIP containing all tenant-owned data in JSON format. Excludes platform-internal tables. Completed asynchronously, download link delivered via webhook.
Data Residency: Enterprise tenants can specify a region constraint. The provisioning API enforces connection string selection from region-tagged vault entries.
